# RAGAS Evaluation

Note: the package installation for the ragas library is known to be buggy, so it was decided to create a seperate
virtual env for the eval as it directly conflicts heavily with the other parts of the app

This directory contains scripts and utilities for evaluating the StudyGraph RAG pipeline using the **RAGAS** library.

## Prerequisites

- Python 3.12 (see the project setup instructions).
- `OPENAI_API_KEY` set in your environment.
- Evaluation dependencies installed (this also installs the backend requirements):

```bash
cd backend
python -m pip install -r eval/requirements.txt
```

## Running the evaluation

Run the module from the `backend` directory so its `app`, `services`, and other backend imports
resolve correctly:

```bash
python -m eval.ragas_evaluation
```

The script loads `backend/.env`, indexes supported files from `eval/docs/`, and evaluates the RAG
pipeline. The default mode is `manual`: it loads questions from `eval/data/*.jsonl`. Each JSONL
row must contain a `question` and may contain a `ground_truth`.

To generate synthetic questions from the documents instead, run these commands from `backend/` in
PowerShell, (note: run this the first tiem to understand the structure of the jsonl file):

```powershell
$env:RAGAS_MODE = "synthetic"
python -m eval.ragas_evaluation
```

By default, synthetic mode generates 10 questions. To choose another count, set
`RAGAS_TESTSET_SIZE` before running:

```powershell
$env:RAGAS_MODE = "synthetic"
$env:RAGAS_TESTSET_SIZE = "20"
python -m eval.ragas_evaluation
```

Here, `RAGAS_MODE` selects `synthetic` or `manual`; `RAGAS_TESTSET_SIZE` sets the number of
synthetic questions. These are environment variables, not command-line flags. Both modes require at
least one supported document directly in `eval/docs/` (`.pdf`, `.docx`, `.pptx`, `.txt`, or `.md`).
The evaluator processes all supported files in that directory.

The evaluation calls `engine.rag_query` for each question and writes a timestamped JSON report to
`eval/reports/`. Synthetic questions are also saved to `eval/reports/generated_testset.jsonl`.
It always computes answer relevancy, and computes these additional metrics when every question
has a ground truth:
- **faithfulness**
- **answer_similarity**
- **context_recall**

## Interpreting the report

The JSON file contains a list of dictionaries, one per sample, with the following keys:
- `question` – the original user query.
- `answer` – the answer generated by your RAG pipeline.
- `ground_truth` – the optional reference answer.
- `contexts` – the text chunks retrieved for this query.
- Metric scores (`answer_relevancy`, `faithfulness`, `answer_similarity`, `context_recall`).

Higher scores indicate better performance. You can aggregate the scores (e.g., mean) to get an overall view of your system.

## Custom test data

Place one or more JSONL files in `eval/data/`. Each non-empty line should be a JSON object with a
`question` field and, optionally, a `ground_truth` field. The `contexts` field is not needed; the
script retrieves context from the indexed documents.

## Extending the evaluation

- **Additional metrics**: Import any other RAGAS metrics and include them in the `metrics` list.
- **CI integration**: Add a Makefile target:

```makefile
ragas-eval:
	cd backend && python -m eval.ragas_evaluation
```
